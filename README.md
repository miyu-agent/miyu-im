# Chat platforms (im)

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This is a Miyu package that connects the AI to chat platforms, so you can talk to the AI in private chats and in group chats. It currently supports QQ (through a reverse WebSocket connection from a OneBot v11 implementation such as NapCat) and Telegram (through the official bot API). This package is not installed together with Miyu's release archives; if you want to use it, you install it yourself.

The core's code lives in the [`miyu-agent/miyu`](https://github.com/miyu-agent/miyu) repository. This repository pins one commit of the core through the git dependencies in `Cargo.toml`.

## What is inside

The table below lists the directories in this repository and what each one is for.

| Directory | What it is |
|---|---|
| `crates/miyu-im/` | The chat platforms host: it handles venue sessions, group chats, plugin hook points and the tools given to the model. It does not depend on any particular platform, and it does not depend on the drivers |
| `crates/miyu-im-app/` | The program `miyu-im`: it hands each platform's driver to the host. The core starts this program and exchanges protocol messages with it over standard input and output. The integration tests that start the real program are here too |
| `crates/miyu-im-onebot/` | The OneBot v11 driver: NapCat connects back to this driver, and the driver feeds messages into venue sessions and sends the AI's replies back to QQ |
| `crates/miyu-im-telegram/` | The Telegram driver: it uses the official bot API and receives messages by long polling |
| `crates/miyu-im-sponsor/` | The sponsor record plugin; its program is `miyu-im-sponsor` |
| `crates/miyu-chat/` | The group chat kernel: the part of chat platforms that does not depend on any particular platform (venue rules, inbound chain, proactive reply decisions, judge, outbound chain). It is pure logic; other platforms that need it can use it through a git dependency |
| `im/` | The package folder (package id `im`): it holds the manifest `package.toml`, the package's own pages `site/`, and `data/` (shipped data that the OneBot bridge reads itself, and the text shown to the model) |
| `im-sponsor/` | The package folder of the sponsor record plugin (package id `im-sponsor`) |
| `docs/blueprint/` | Design blueprints: `onebot.md` (the OneBot bridge) and `chat.md` (the group chat kernel) |
| `docs/ledger.md` | The ledger: it records every piece of text in `im/data/` that the model sees |
| `xtask/` | The gate: `cargo xtask check` |

## Install

This section shows how to install the package. Install Miyu first, then run:

```sh
miyu pkg install im
```

The sponsor record plugin is a separate package, `im-sponsor`, and installs the same way. To connect QQ and Telegram, choose who can talk to the AI and set the rules for groups, see [Chat platforms](https://github.com/miyu-agent/miyu/blob/main/docs/en/guide/heads/im.md).

## Build from source

This section shows how to build the package yourself. You need Rust (the version is set in `rust-toolchain.toml`, and `rustup` installs it automatically) and git (cargo fetches the core's code through git dependencies). Run:

```sh
cargo build --release -p miyu-im-app --bin miyu-im
```

Put the built program into the `bin/` directory of the package folder `im/` (on Windows the file name ends in `.exe`; `im/bin/` is not tracked by git), then install that folder:

```sh
mkdir -p im/bin
cp target/release/miyu-im im/bin/
miyu pkg install ./im
```

The package id comes from the folder's name, so you must install a folder named `im` (this package's configuration keys are `im.*`, and the sponsor record plugin's are `im-sponsor.*`). If the program is not in `bin/`, the core treats the package as not installed.

## Gate

The gate is a set of checks that code must pass before it is committed. Run:

```sh
cargo xtask check
```

This command runs, in order, the format check, `clippy` (`-D warnings`), the docs check, the ledger reconciliation, the pure logic check (the group chat kernel must not touch I/O or clocks), the line count check (no `.rs` file over 500 lines), the license check and the tests, and finally prints a table of results. CI on all three platforms runs the same command.
