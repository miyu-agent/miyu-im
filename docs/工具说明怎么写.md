## 工具说明怎么写

给模型看的工具说明（`im/data/onebot/tools/*.json` 的 `description` 和参数）怎么写。2026-10-21 施工 I-20 总结：参照 OpenAI Codex（`codex-rs` 的 `*_spec.rs`，调研存档 `~/.cache/miyu-harness-survey-2026-09-28/codex.md`）写工具的办法，照它把桥的十五件从 1587 个 token 改到 1415 个，预算不动。

工具说明在 tools 数组里，每次请求都带，一个字一直在花钱；所以门禁只查预算，超了改说明，不提预算。

### 一、Codex 是怎么写的

- **说明一句话，说它做什么、给回什么**。`exec_command`：「Runs a command in a PTY, returning output or a session ID for ongoing interaction.」`view_image`：「View a local image file from the filesystem when visual inspection is needed.」最长的 `update_plan` 也只有三行，第三行是唯一的规矩（「At most one step can be in_progress at a time.」）。
- **参数说明一句，名字看得出的不写**。有就是一个短句，默认值写在句里（「Defaults to 10000 ms.」）；`plan` 的每一项只写「Task step text.」「Step status.」。
- **能用枚举的用枚举**，不用一句话解释能填什么。
- **什么时候用、怎么用不写进工具**。`update_plan` 的用法（什么时候值得列计划、好坏例子）写在系统提示词里；给 Codex 系列模型的提示词更进一步，去掉了整节工具指南，只留一句计划工具的取舍，别的靠工具自己的说明。
- **上限交给代码和报错**。`yield_time_ms` 超了代码夹回范围，进程号不对回「Unknown process id …」，模型照报错改；说明里不列每个上限。
- **报错是给模型读的**，说清哪里不对、怎么改：「stdin is closed for this session; rerun exec_command with tty=true to keep stdin open」。
- **名字用模型熟的**：代码里叫 `process_id`，给模型的仍叫 `session_id`，注释写着「The model is trained on `session_id`」。

### 二、我们的写法

1. **说明一句**：做什么。对象有默认的（「没写人的照你在回的那条」），这一条写进同一句。第二句只留给最容易错的一条规矩（`qq_skip_reply`「Use it when…」、`qq_send`「For the chat you are in, just reply.」）。
2. **参数先问名字、类型、枚举说清了没有**：`user`、`users`、`group`、`query`、`limit`、`kind`、`view`、`period` 都不写说明。要写的只有名字说不清的：`msg`（「The msg= id.」，对上近况里的 `msg=`）、`index`（「The #n item. Default 1.」）、`seconds`（「0 unmutes.」，看不出怎么解禁）、`block`（踢之外还做什么）、`reason`（进管理记录）。
3. **默认值写成「Default N.」**，上限不写：超了的由代码挡、报错说范围（`limit must be 1 to 200`、`bad-seconds` 照设置报最短最长）。写死在说明里的上限还会和设置对不上（禁言最长是设置项，说明写 2592000 就是错的）。
4. **调用以后才用得上的写进结果**：存在哪（`Saved to {path}.`）、列表每一行什么意思、没找到怎么办，都在 `tool-results/` 的句子里，说明里不写。
5. **用法、场合不写进说明**：「拿它找要发给谁」这类教用法的去掉；真要教的写进事实或系统提示词，并且照登记簿的规矩先实测证明不加不行。
6. **英文短句**，不用分号串、不用「总述：分述」。

### 三、改了怎么验

1. 量：`~/.cache/miyu-remake/d4b/measure/toolface.py im/data/onebot/tools`（「带工具减不带」的边际份量和合计，端点、key 照脚本旁边的说明，不写进仓库）。
2. 合计不超过 `crates/miyu-im-onebot/tests/budget.rs` 的预算（字节）和登记簿里记的 token 预算；超了接着改说明。
3. 登记簿（`docs/ledger.md`）每份改过的换 token 数、指纹，理由一栏写改了什么、为什么能删。
4. 改说明是一次计划内的缓存冷启动：tools 数组变了，前缀从头算；改完以后照样是常量字节。

### 四、没照搬的

- Codex 每个对象都写 `additionalProperties: false`：那是给严格模式用的；我们的参数由驱动自己认，写上只多花 token。
- Codex 把低频工具收进命名空间、按需搜出来（`tool_search`）：桥的工具面由核心照 `venues` 和开关放，按需加载是核心的事，不在这里做。
