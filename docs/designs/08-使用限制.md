## 设计 08：使用限制

状态：已定（2026-11-05 项目主人定）。

### 一、要什么

项目主人问：能不能按人、按会话卡片限 token 用量，每五小时、每周、每月三条线一起设。11-05 定了：

1. **两种限制**：
   - **会话卡片**：每个会话自己的三条线，在会话卡片上设。一张卡一个会话，「陌生群」「陌生私聊」卡管名单以外的每一个会话，会话默认值管没写这一格的。这和限流一样，各算各的，不是几个会话合起来算。
   - **每人**：在一页专门的「使用限制」上设，一个人在所有群和私聊里的用量合起来算。页上有一组默认的三条线，对所有人生效；下面可以单独给某个人另设三条线，或者设成不限。
2. **三条线**：最近 5 小时、最近 7 天、最近 30 天，都是滚动窗口，和限流一样，没有固定的重置时刻。哪一条没写，那一条就不限。碰到任何一条就算满。
3. **按什么数算**：读缓存、没命中、写缓存、输出四项加起来，和数据统计页的「合计」是同一个数。
4. **不是哪个人叫的请求**：判官、看一眼、压缩这类请求只算进会话的合计，不算到任何人头上。每人的账只算这个人叫起来的那几轮，支线也算。
5. **满了怎么办**：和限流满了一样，只记录，不开回合，QQ 里不发任何提示（O-47）。会话满了的这段时间也不调判官，也不看一眼。人满了的话，只拦这个人的消息，别人照常。正在跑的那一轮不打断，所以会多出最后一轮的量。
6. **豁免**：和限流一样。谁不受限流管，谁就不受额度管，包括终端管理员、白名单成员，以及私聊卡上的「忽略限流」。他们叫起来的用量照样算进会话的合计，页上也照样列出来，只是不拦他们。

### 二、怎么做（技术）

1. **会话的用量从核心的账本取**：桥用自己的连接调 `usage.query {group: ["venue"], from}`，所有连接都能调（核心 `connection/rights.rs`），一条线查一次，三次查完各取各的。查的结果在内存里留 60 秒，过期了在后台再查，不卡住正在过链的消息；先拿上一份判。查失败的话，判成没满，并记一行 WARN：账本坏了不能把所有群都拦住。
2. **每人的用量 im 自己记**：核心的账本里没有「人」这一项。
   - im 本来就订阅着群和私聊会话，每次模型请求核心都会推一条带用量的 `model.called`。
   - 这一轮回的是谁，看 `turn.started`、`turn.joined` 的 `triggers` 里那几条是谁发的，投影里本来就记着。私聊回的就是对面那个人；支线回的是它那个人。
   - 一轮回了几个人的话，用量平分给他们，余数给排在前面的那个。看一眼、终端叫她发 QQ 这类没有触发人的轮次不记到人头上。
   - 记进 `var/lib/miyu-im/usage.db`，一行记会话、事件序号、人、场所、时刻、四项合计，以（会话、事件序号、人）为主键。桥重启以后会照日志重新补一遍事件，主键保证同一条不会记两次。超过 31 天的行每小时清一次。
3. **进站链加一条规则**：放在限流后面，名字叫「额度」，停下的原因是 `QuotaReached`。和限流一样，交进来的是判好的事实（会话满没满、这个人满没满），规则本身不碰 I/O。豁免照限流那一条认。
4. **卡片的三格**：键是 `limit_5h`、`limit_week`、`limit_month`，值是整数 token 数，没写就是不限。放在「限流与并发」那一组，出现的地方和限流一样：群卡、陌生群卡、陌生私聊卡、私聊卡（「忽略限流」关着时才显示）、会话默认值。
5. **每人的设置**：存在 im 配置目录里的 `limits.toml`，由页面写，桥隔一会儿看一眼有没有变，变了就重读（和违规词表一样）：

   ```toml
   [default]
   limit_5h = 2000000
   limit_week = 10000000

   [[person]]
   id = "qq:10002"
   limit_month = 50000000

   [[person]]
   id = "qq:10003"   # 三条都不写的就是不限
   ```

   单独设了的人，整组替换掉默认的三条线，不跟默认的逐条合并。

6. **「使用限制」页**：放在侧栏，紧挨着「数据统计」。
   - 页上有默认的三格，下面是单独设的人的列表，可以加、可以删，号照平台写。
   - 再下面列出最近 30 天用过的人，按最近 5 小时的用量排，最多 50 个。每人写名字、号，三条线各用了多少、上限是多少，满了的标出来。
