## 设计 01：接入通讯平台（草案）

状态：草案，2026-10-19 起草。第一节是项目主人当天定的；第二节到第十节是照推荐写的技术形状；第十一节是施工的先后。项目主人先自己看完，再发给核心、WebUI、表情包的会话对。这一份重开核心仓库设计 `18-通讯平台.md` 的 Q1（一个平台一个桥、共用群聊内核）和第十七节「未选：同时接 Telegram、Discord」，要和核心的会话对过。

起因：现在只接了 QQ，但通讯平台远不止一个（AstrBot 接了十几个）。照设计 18 的路，以后每接一个平台就是一个新的桥，场所卡片、白名单、陌生人、长文、出站队列、插件挂接点、后台页都要再写一遍，给 QQ 写的插件到别的平台用不了。项目主人问：是做一个统一的通讯平台接入，还是每个平台一套页面和插件系统。

### 一、定了的（2026-10-19 项目主人定）

1. **一个统一的接入包，平台是驱动**：一个包、一个进程、一套页面、一套场所卡片、一套插件挂接点。OneBot（QQ）是第一个驱动，以后的平台都是加驱动。驱动先放在进程里；以后真有第三方要用别的语言写驱动，再给驱动开一个进程外的协议，插件不用改。
2. **名字**：显示名「接入通讯平台」（原来的「接入QQ」）。WebUI 里的入口跟着改名。
3. **先后**：先写这份设计、和核心对过，再拆分（挂接点和工具改名、宿主和驱动分开、包改名），最后在新的形状上做页面。
4. **页面自己提供**：不装 WebUI 也能用。桥带一个页面服务，`miyu <命令> web` 打开本机的网址。登录用 Miyu 的账号（和 WebUI 同一套，核心验）。
5. **WebUI 里是跳转**：WebUI 的入口点了跳到桥自己的页面，不再把页面嵌进 WebUI 的框里。这样页面只有一种跑法，页面替人做事靠的是人的登录，不用放宽核心对扩展的规矩。
6. **页面的样子**：左边侧边栏切页、右边是页面内容。
   - 首页：没连接时一个「新建连接」，一步步引导配好，配好了带人去第二页；连接配好以后首页显示运行状态、日志、各项数字。
   - 第二页：群聊和私聊，卡片式，带头像。新建、编辑都在浮动窗口里，浮窗里像 WebUI 设置页那样分页，比它大一些。
   - 第三页：软件商城，要做，等软件源做好再做。
   - 第四页：已安装的插件，像 AstrBot 的插件详情页，带设置；插件自己带面板的，详情页上有醒目的跳转。
7. **主题**：从 WebUI 跳过来的跟 WebUI 的主题；单独打开的用页面自带的一套默认主题（浅色「晨光」、深色「tokyonight」，同 WebUI 出厂的）。
8. **浮窗分页的扩展口现在就定，声明式**：插件能往场所的浮窗里加分页（以后的消息记录、群管理记录这类）。
9. **不装 WebUI 时插件的面板也能开**：桥照 WebUI 给后台页的那套规矩（隔离的框、不许联网、只能做三样事）给插件的面板开框。
10. **会话卡片的格、设置页**：见第八节第 6、7 条（2026-10-19 项目主人定）。
11. **包的编号 `im`**：命令 `miyu im …`、配置键 `im.*`、仓库 `miyu-agent/miyu-im`（第七节）。
12. **从 WebUI 跳过来免登录**：核心加一张一次性的交接票（第九节第 3 条）。
13. **插件属于 im，不属于平台**：`miyu-im-<名字>` 的包就是 im 的插件，写一次，哪个平台都能用；插件管理是 im 网页里的一页，不是每个平台一份（第四节）。
14. **每个场所能单独开关插件**：场所浮窗里多一页「插件」（照 AstrBot 的会话管理）。
15. **插件往 im 界面加东西，声明式为主，另留沙箱框**：首页卡片、场所浮窗分页、插件自己的整页都用声明式；要自己写 HTML 的复杂面板照旧走沙箱框。
16. **插件能往首页放卡片**：人可以调顺序、藏起来（照 MaiBot 的首页卡片）。
17. **不要 `/qq-groups`、`/qq-friends` 两个整页**：会话的设置只在 im 自己的页面上。加一个命令 `/im`，直接打开 im 的页面；WebUI 设置里「软件后台」列着 im，点了跳到 im 自己的页面。
18. **界面上的字在 `01-接入通讯平台-界面文字.md`，配置项在 `01-接入通讯平台-配置项.md`**（每一项写清它管什么、默认、键、旧版叫法，留「改成」两行），项目主人在那两份里改，样板、施工都照它们。
19. **改人格当场生效**：先压缩这个会话，再换人格接着聊（要核心第 6 件）。
20. **每个会话的模型有四种**：对话、看图（要核心第 5 件）、主动回复判断（im 自己的 `judge.model`，现在就能做）、旁路请求（入群审批这类，功能做出来时一起）。
21. **上下文条数归 im**（核心的会话 10-19 回：`venue.session` 多 `recent`，按条数，默认照现在的字数预算换算，字数预算照旧做上限、两个取小的，造会话时钉死）：「判断时看前几条消息」（`judge.records`）、「回复时带多少条群聊记录」都是 im 的配置项、按会话存；后一样由 im 造会话时交给核心（核心多认一个参数，群聊记录照旧由核心放进请求，不打乱前缀）。不用 `system.append` 自己塞：system 末尾每条都变会打掉缓存，日志里也有了会重复。
22. **识人术做成内置插件**（2026-10-19 项目主人提）：`miyu-im-identity`，跟 im 一起装、默认开。O-53 写在桥里的冒充提醒（保护终端管理员的名字、AI 自己的群名片）挪进它；加上识人映射（用户 ↔ 号码的表，旧版有）。暂时只支持 QQ（声明文件里 `platforms = ["qq"]`，2026-10-19 项目主人定）。做成 OneBot 驱动里内置的插件（代码在 `miyu-im-onebot`，跟驱动在一个进程里；2026-10-19 项目主人定：这是 OneBot 的识人术插件）：宿主留一个口子让驱动交出自己带的内置插件，照样是 im 插件（声明、场所开关、插件页标「内置」），不能卸载。设置在插件页，不在 im 的设置页：号码属于具体平台，又是可选的功能，正好当 im 插件的第一个示范。
23. **不只 NapCat**：QQ 能连任何支持 OneBot 协议的软件（NapCat、SnowLuma、LLOneBot、Lagrange……）。新建连接的字照项目主人给的写（`01-接入通讯平台-界面文字.md`），不再分实现给路径。
24. **被叫时也过主动回复判断**做成开关，出厂开（同现在；旧版叫「接管直接触发」）。「跳过主动回复判断的用户」照旧版：叫 AI 直接回，没叫的只记录。
25. **统计页先看 token**：token 消耗、构成、请求构成放最上面（第八节第 5 条）。
26. **代码拆成「库」和「平台」两个 crate，还是一个进程、一个包**（2026-10-19 项目主人提、定的拆法 A）：`miyu-im`（宿主，和平台无关的都在这里）+ `miyu-im-onebot`（OneBot 驱动），编进同一个程序；边界由编译器守（宿主不依赖驱动的 crate）。以后真有第二个平台、第三方驱动时，再把驱动的 trait 升成协议、拆成两个包（第四节第 7 条）。
27. **仓库也改名**：GitHub 上 `miyu-agent/miyu-onebot` 改成 `miyu-agent/miyu-im`，本地检出 `~/Documents/github/miyu-agent/miyu-im`，remote 跟着改（2026-10-19 项目主人提）；和包改名一起做（I-4）。

### 二、分层

| 层 | 在哪 | 管什么 |
|---|---|---|
| 核心 | 核心进程 | 不变：场所会话、外部身份绑定、旁听、回合闸、分叉、`model.call`。本来就不认识平台 |
| 群聊内核 `miyu-chat` | 这个仓库的库，纯逻辑 | 不变：场所规则、进站链、线路规程、判断、出站链 |
| **宿主** | 接入通讯平台的进程里，和平台无关 | 现在桥里平台无关的部分都挪到这里：场所卡片、白名单、陌生人、长文、仅发送最终消息、出站队列、退信、贴表情的时机、补发、命令、挂接点、页面服务、登录 |
| **驱动** | 同一个进程里，一个平台一个 | 只管平台：连接（OneBot 是反向 WebSocket）、消息的编解码、quirk 表、平台动作（发、撤回、禁言、戳、贴表情、取成员、取头像、取图、合并转发）、平台的通知 |

宿主只经驱动的接口碰平台（第三节）。宿主里不出现 OneBot 的动作名、消息段、`napcat` 这类字；`qq` 只作为场所编号、外部身份里的平台前缀出现（本来就是 `qq:group:<群号>`、`qq:<号>`，不用改）。

### 三、驱动的接口

一个 Rust 的 trait（照推荐定，施工时细化）：

1. **认得自己**：平台名（`qq`）、显示名、图标；连接设置要哪几格（声明式，页面「新建连接」照它画，第八节）。
2. **进来的**：统一的消息（场所、发的人、平台上的消息编号、时刻、内容段：字、图、@、引用、表情、文件、合并转发……认不出的段带原样）、统一的通知（撤回、禁言、戳、加好友、进群退群）、连接的状态（连上、断开、是哪个实现哪个版本、机器人的号）。
3. **出去的**：发消息（一段段统一的内容）、撤回、禁言、戳、贴表情、取成员、取头像、取一个媒体、取一条消息、合并转发……每一样是一个方法，驱动做不到的回「不支持」。
4. **能力表**：这个平台支持哪几样（第 3 条）。宿主照它决定工具有没有、长文能不能合并转发、能不能贴表情。
5. **quirk 表**：各家实现的怪癖关在驱动里（设计 18 第十三节）。
6. **原始接口**：插件要平台独有的功能时，经宿主转给驱动的原样调用（OneBot 是动作名加参数），宿主不解释。

### 四、插件

参考了 AstrBot（插件默认不分平台、消息链、`support_platforms` 只展示、按会话开关插件、iframe 插件页）和 MaiBot（清单逐项声明能力、平台适配器本身是插件组件 `MessageGateway`、纯声明式的 `webui.json`、首页卡片 `HomeCard`）。

1. **插件是什么**：一个 Miyu 软件包，名字照约定叫 `miyu-im-<名字>`（约定，不强制）。清单里依赖 im（核心的依赖，设计 31 第三节），再写一张 `[content.im] dir = "im"`：给 im 带一个目录（核心已有的「给别的包带的内容」，`packages.md`，核心不用改）。im 经 `content.list`、`content.read` 读它，装、卸、升级了核心推 `content.changed`。
2. **声明文件** `im/plugin.toml`（字段施工时细化）：
   - 显示名、一句说明、图标；主页、仓库、问题反馈三个链接；README 的路径（详情页「介绍」照它画）。版本、作者、许可证照核心的清单。
   - `platforms`：写了的只在这几个平台上挂（`["qq"]`）；不写的是「哪个平台都行」。
   - `needs`：要用的平台能力（撤回、合并转发、贴表情……，第三节第 4 条的名字）。im 照每个驱动的能力表算它在哪些平台上能用；用不了的平台上不挂，插件页写明缺哪一样。比 AstrBot 的 `support_platforms` 只展示多一步。
   - 挂在哪几处（第 3 条）、往界面加什么（第 5 条）。插件没在跑也照它显示，以后商城照它显示。
3. **挂接点**：现在的 `qq.event`、`qq.inbound`、`qq.outbound`、`qq.score`、`qq.action`、`qq.venue`、`qq.send` 改成 `chat.event`、`chat.inbound`、`chat.outbound`、`chat.score`、`chat.action`、`chat.venue`、`chat.send`。
   - 参数多一格 `platform`；内容段照第三节第 2 条的统一写法，认不出的段带原样（同 AstrBot 的 `raw_message`、MaiBot 的 `additional_config`）。
   - `chat.action` 是第三节第 6 条的原始接口：`{platform, action, params}`，插件写给哪个平台自己知道。
   - 只问在这个场所开着的插件（第 4 条）。
   - 0.8.0 还没发布，不留旧名字的别名。用到的只有表情包，一起改。
4. **开关**：
   - 总开关是核心的包开关（`package.enable`、`package.disable`），在 im 的插件页上用人的登录做（第九节）。
   - 场所开关：场所浮窗里一页「插件」，列能在这个平台上用的插件，一个一个开关。存在场所卡片里；「陌生群」「陌生私聊」卡上的是兜底的默认。新装的插件在没设过的场所里照它声明的默认（不写的开）。
5. **往 im 界面加东西**（声明式为主）：
   - 三处：首页卡片（人能调顺序、藏起来，布局记在 im 那边）、场所浮窗分页、插件自己的整页（在插件详情里打开）。2026-10-20 项目主人定
     （施工 I-8 下）：首页卡片只在插件详情里开关「放在首页」，顺序照插件的编号、不能调；浮窗分页只在这个插件在这个会话开着时出现；
     整页在插件详情头上一个整页一个按钮。插件在 `plugin.toml` 的 `[plugin.ui]` 里声明这三样（`home`、`panel`、`pages`）。
   - 写法用核心的「界面块」（`widgets.md`：分组、表单、列表……）；统计、表格、图表这类缺的组件补进核心的界面块，终端以后也能画。
   - 数据经插件导出的方法取：`chat.panel {venue, platform}` 交浮窗分页，`chat.home` 交首页卡片，整页照声明写的方法名。只调得到它自己导出的方法；表单提交经 im 转回它。改东西的操作要写确认的一句（照 MaiBot）。
   - 等不到的、写错的那个插件的那一块不画，别的照常；记一行运行日志。
   - 要自己写 HTML 的复杂面板：照核心的后台页（`[page]`），im 照 WebUI 的规矩开沙箱框（第九节第 5 条）；插件详情页上一个醒目的「打开面板」。
   - 2026-10-23 项目主人重申：插件按需要挑这几种方式，可以几种都用。跟某个群、某个人有关的放浮窗分页；跨群、跨连接的数据和设置放自己的后台页（「打开面板」）。**共用的包只写一份后台页**：网页软件的「软件后台」和 im 的插件页（包写了 `[content.im]` 的）打开的是同一份文件，不给两边分别做适配，页面怎么画是作者的事（表情包包的偷图就这样，两边都有）。im 开面板时把从哪个平台、哪个连接进来的交给页面（网址片段里），页面要不要按连接分由作者定。不写 `[content.im]` 的包（语音这类）只在网页软件里有。
6. **内置插件**：跟 im 一起装、默认开的插件照样是一个 im 插件（同样的声明文件、挂接点、开关），只是出厂就在。现在两个，都只支持 QQ：识人术 `miyu-im-identity`（第一节第 22 条）、群管理 `miyu-im-qq-admin`（设计 02）。插件要往会话里记一句给 AI 的事实（识人术的冒充提醒、群管的「X 被 Y 禁言 10 分钟」），会话归 im 的系统账号、插件写不进去，所以 im 留一个口子：插件调 im 导出的 `chat.note {venue, kind, text}`（施工 I-8 上定：只这一条路，挂接点的回答里不带 `note`）；im 照现在事实的写法（英文、XML 标签、转义）经核心的 `session.note` 记进那个会话，不开回合。
7. **以后驱动也可以是插件**：MaiBot 的平台适配器就是插件组件。第三方要写驱动时，驱动就是一个在 `im/plugin.toml` 里声明自己是驱动的 im 插件，经约定的方法收发、报连接状态（第一节第 1 条说的进程外协议就长这样）。现在先不做，第三节的 trait 照这个形状留。

### 五、工具

撤回、戳一戳、@ 指定的人、取头像、群成员、主动发消息（现在的 `qq_send`）、取图、查聊天记录改成不带平台的名字。2026-10-20 项目主人改：工具都在驱动里（施工 T-1..T-4），名字统一加驱动平台的前缀（OneBot 是 `qq_`：`qq_recall`、`qq_send`……，施工 I-12）：以后别的驱动的工具同在 im 一个包里，不加前缀会撞名。设计 18 第十一节「改场所规则」不做给 AI 的工具（2026-10-20 项目主人定）：改白名单用命令行 `miyu im whitelist`，终端里的 AI 用 shell 调（施工 I-13）；场所总览不做；通讯录、群文件、贴表情只给 QQ 的会话（施工 I-12）。禁言挪进群管插件（设计 02，2026-10-19 项目主人定）；AI 自己被禁言的处理（O-50）照旧在 im。一个场所会话的平台是固定的，工具面照驱动的能力表算一次，会话里字节不变（前缀稳定第一）。改名是一次计划内的前缀变化。

2026-10-20 项目主人定：**工具都在驱动里，im 不提供工具**（「不同平台的插件、工具最终调用的接口可能是完全不一样的。onebot 的工具应当在 onebot 里」）。im 是接入通讯平台的内核（会话、回不回、进出站、插件系统、页面），留一个口子（`crate::toolset::ToolSet`）让驱动交它的工具：有哪几件、说明和答的话在包文件夹 `data/<驱动>/` 下、一次调用怎么办；im 照会话填好场景（发到哪、机器人号、谁叫的、工作区、那个机器人号的连接）交过去，路由上的事（这一轮不说话、@ 谁、发消息）由 im 照驱动交回的办。群管理也做成 OneBot 驱动带的插件（同识人术）。照这个分几张施工单挪：T-1 口子和头像、群成员，T-2 撤回、禁言、戳一戳，T-3 取图片文件，T-4 主动发消息、@ 人、不回复；挪完 im 那张工具表是空的。工具名、给模型看的说明一个字不改。

### 六、配置

- 宿主的：白名单、睡觉时间、触发词、看得到号、去句号、撤回回执的命令……键是 `<包编号>.<名字>`。白名单里本来就写平台前缀（`qq:<号>`），多平台不用改写法。
- 驱动的：连接的那几格（OneBot 的端口、令牌）。键是 `<包编号>.<平台>.<名字>`，例如 `im.qq.listen`、`im.qq.token`。核心的设置名原来不能带点；2026-10-19 项目主人定照这个写法（不改成 `im.qq_listen`），清单里写 `[settings.qq.listen]`；核心 9287d31d 起认一层组，施工 I-3 补换上（页面服务的端口同样是 `im.web.port`）。代码里驱动报自己的配置项（`Driver::settings`），宿主挑出来交给它（I-3）。
- 场所卡片：照场所编号存，本来就带平台；「陌生群」「陌生私聊」两张兜底卡一个平台各一张。

### 八、页面

1. **侧边栏**：首页、会话、平台会话（2026-10-23，第 9 条）、插件、商城（软件源做好以前灰着）、统计、设置（统计放在设置上面，2026-10-19 项目主人定）。头上一行是名字「接入通讯平台」和在线状态，左上角一个收起、展开的按钮；收起、展开、收起以后指针靠到最左边临时浮出来，都照 WebUI 的左栏（`styles/sidebar.css`：展开先快后慢 0.28 秒，收起先慢后快 0.26 秒）。不另画标志。
2. **首页**：
   - 一个连接都没有：正中一个「新建连接」。进去第一步选平台（现在只有 QQ），后面的步子照驱动声明的连接设置一步步画：QQ 是「在支持 OneBot 协议的软件里新建反向 WebSocket（复制地址，按钮「我已填写」）→ 获取反向 WebSocket 验证 Token（按钮「保存并连接」）→ 等它连上」。等的时候画两个节点之间一条线、光点来回跑，连上了画一个勾，不用 emoji，连上了庆祝一下，按钮「去设置群聊和私聊」。令牌只有一个：那边创建反向 WebSocket 时多半自动生成，粘贴过来，两边一样（2026-10-19 项目主人指出：原来的「生成令牌」像是 im 另有一个令牌）。连上以后连接卡写实际连上的实现和版本。
   - 有连接以后：「连接」一栏，一个机器人账号一张卡，多了照网格排开。头像是机器人账号在平台上的头像（驱动取），右下角是平台的角标；卡上写名字、平台和实现（「QQ · NapCat 4.8.93」）、机器人的 ID、在线状态和连了多久（断开的写在重连）；齿轮按钮打开连接设置（驱动声明的格，QQ 是反向 WebSocket 端口、NapCat 的 Token、NapCat 那边的地址）。侧边栏头上的状态写几个机器人、有没有在重连的，下面是今天的数字（收到、回复、只记录的、退信）和插件放的首页卡片（第四节第 5 条，人能调顺序、藏起来），再下面是最近的运行日志（只读，能按级别筛）。数字和日志由宿主登记方法交（第九节）。
3. **会话**：卡片墙。连着不止一个平台时，上面先切平台（只有一个平台时不出现，2026-10-19 项目主人定）：做成下拉的列表，不是一个平台一个按钮（平台以后会多），列表能搜，每一项写几个机器人、几个会话，没连上的灰着；再筛「全部」「群聊」「私聊」，能搜。全部里分三段：名单以外（「陌生群」「陌生私聊」）、群聊名单、私聊白名单。私聊白名单就是私聊的卡：加一个人就是加进私聊白名单，设置页不另放。右上角一个「新建」：先选群聊还是私聊，再一个搜索框：「输入群号搜索或添加」「输入 QQ 号搜索或添加」，搜到了（AI 在的群、好友）就用，搜不到就照填的号直接新建（2026-10-19 项目主人定）。私聊白名单要先加，对方加 AI 好友时才自动通过，所以不能只从好友里选。加好了接着打开它的浮窗。同一个平台连着几个机器人时，卡上的 ID 后面写是哪个机器人。一张卡一个会话：头像、名字、ID、平台角标、是否回复的开关、几个说明它怎么设的小标签。「陌生群」「陌生私聊」两张兜底卡放在最前。新建、编辑都弹浮窗：左边分页，右边内容，比 WebUI 设置页大。头像由驱动取（宿主取来交页面）。格见第 7 条。开关管着的几行，开关关着时藏起来，不变暗。
4. **统计**（2026-10-19 项目主人提；看统计主要是看 token，放最上面）：能按平台筛（下拉），时间段今天、7 天、30 天。三段，从上往下：
   - **token**（照核心的用量账本 `usage.query`，扩展能读，按会话、模型、天、用途分组；参考 AstrBot 的统计页）：token 合计、缓存命中率、每次回复平均（含这一轮的判断、看图）、模型请求次数，都和上一段比；每天的 token（读缓存、没命中、写缓存、输出、思考叠着画）；token 构成（五样各占多少）；请求构成（按用途：回复、主动回复判断、看图、压缩、旁路请求，各多少次、占多少 token）；用得最多的会话（能点开它的浮窗）；按模型。金额算不准不显示（项目主人的规矩）。AstrBot 有的首字延迟、调用成功率核心现在不记，先不做。
   - **消息**：收到、回复、回复率、没发出去；每天的消息；最热闹的会话；为什么回、为什么没回（叫了 AI 直接回、抽中判断回了、判断了没过门槛、限流满了、睡眠时间、跳过）；一天里按小时的热闹程度。数字由宿主照判断和发送记（按天、按会话、按判断结果、按小时），存在 im 自己的状态目录里。
   - **运行**：运行时间、进程内存、CPU（接入通讯平台自己的进程）、插件（几个开着、几个出错）。
5. **插件**：装了的 im 插件一张卡一个（名字、图标、状态、总开关、挂在哪几处、在哪些平台上能用）。点进去是详情页：头上是名字、包名和版本、主页·仓库·问题反馈三个链接、总开关、有沙箱面板的一个醒目的「打开面板」；下面三页：介绍（插件带的 README）、设置（照核心的 `config.schema` 画）、用在哪（在哪几个会话开着，能直接开关）；右边「关于」：版本、作者、许可证、挂在哪、哪些平台能用、开着的会话、要的权限。开关、改设置用人的登录做（第九节），不放宽扩展的权限（第四节）。
6. **设置**（2026-10-19 项目主人定：通用设置是平台自己的设置页，不和会话设置放在一起）：
   - 只放 im 自己的、各平台通用的设置（2026-10-19 项目主人定）；平台自己的连接设置在首页的连接卡上，私聊白名单在会话页。
   - **会话默认值**：第 7 条那些格的全局默认（各平台通用的格）。两层：设置页是默认，卡片只写和默认不一样的；新加的群、新加的人是空卡，照出厂和这里的默认（2026-10-19 项目主人定）。「陌生群」「陌生私聊」只管名单以外的会话。
   - **账号绑定**：平台身份 → Miyu 账号（核心的 `external.bindings`，原来的「终端管理员」）。旧版的「允许使用终端的管理员 QQ 号」「是否允许非管理员使用电脑」是单用户的做法，不搬：多用户就是多绑几个，权限归核心管。
   - **通用**：去掉末尾句号、撤回回执的命令。
   - **网页服务**：端口；登录用 Miyu 账号。
7. **会话卡片的格**（2026-10-19 项目主人定；每一格的名字、小字、它管什么、默认、键在 `01-接入通讯平台-配置项.md`，以那一份为准，这里只写分页）：
   - **叫法由驱动给**：界面上不写死「QQ 号」「群号」，设计里叫「用户 ID」「群 ID」。
   - 浮窗的分页：概况（是否回复、今日消息、最近判断）、人格和模型（AI 人格、额外提示词、四种模型、回复时带多少条群聊记录）、触发方式（只有群聊）、限流与并发、发送消息处理、管理插件，插件声明的分页排在后面。
   - 开关管着的几格，开关关着时藏起来；「高级」默认收起。
   - 私聊卡没有「触发方式」「会话内并行数量」，多「忽略限流」「忽略睡眠时间」（默认是）；「陌生私聊」卡有是否回复、限流，没有两项「忽略」。
8. **目录**：页面的文件拆成外壳（侧边栏、路由、主题、和桥说话的那一层）、各页（一页一个文件夹）、字（三种语言）。
9. **平台会话**（以后改成「消息记录」页：读 im 自己的聊天记录库，见设计 04；2026-10-23 项目主人定：场所会话只读，人的头不许直接往里发话、打断、改设置，看的地方放进 im 自己的后台页；「一个平台会话页，点击后按照连接（不同平台或者同平台不同连接）显示会话」；管理员能删）：侧边栏「会话」下面一项。
   - 进去先按连接分组：一个连接一组（平台角标、机器人的名字和号），组里列这个连接收进来的会话（群名或人名、号、群聊还是私聊），从新到旧；还没来过消息、认不出是哪个连接的放在最后一组。
   - 点一个会话进它的记录：只读，和终端、网页看会话画的是同一份视图条目（人说的、她的回复、工具那一步收起成一行、旁白）；人说的每一条旁边一个小标签「回了」「只记下 · 为什么」（限流、复读、睡觉时间、判官说不回……），点开看判官的理由。往上翻接着读更早的；页面开着时有新消息就重读最新一页（桥的推送，不轮询）。

   - 谁能看：只有管理员组的人（等核心 Y-2 下的管理员模式）；在那之前照本机才能开。
   - 桥那一头的方法（施工 I-34 上，`core/route/browse.rs`）：`sessions.list`、`sessions.page {session, before?}`（核心 `view.page` 的视图条目，多两张表：`judged`，条目编号 → `{outcome, why}`，`why` 同会话浮窗「最近判断」的原因；`names`，条目编号 → 发的人的名字）、`sessions.delete {session}`，都在桥自己的连接上问核心，页面服务照会话页那样经人的连接转。

### 九、页面服务和登录

1. 桥起一个只听本机的 HTTP 服务（端口是宿主的配置项），给页面的文件、页面和宿主说话的通道（WebSocket）、插件面板的框。
2. **登录**：用户名、密码交给核心验（同 WebUI），换到的登录令牌桥只放在内存里，照它另开一条「人」的连接连核心（核心的会话 10-19 定：照头的做法经 `miyu-client` 连本机套接字，登录令牌在握手里带，不另开 WebSocket）；页面上要人的权限做的事（开关插件、改插件的设置、生成令牌这类密钥）走这条连接。没设过密码的照 WebUI 第一次那样用一次性码设。
3. **从 WebUI 跳过来不再登录一次**（项目主人定）：WebUI 先向核心要一张一次性的交接票，带在跳转的网址里，im 拿它换登录令牌。核心的会话 10-19 回的形状：已登录的连接调 `login.ticket` 要一张 60 秒、一次性、绑定同一账号的票，im 调 `login.redeem` 换登录令牌（核心做的时候定死）。
4. **主题**：从 WebUI 跳过来的，网址里带 WebUI 这时的主题和颜色（整套，不只七个）；单独打开的用页面自带的，跟随系统深浅，能手动切。
   - **跳转的写法**（2026-10-19 WebUI 的会话定）：新标签页打开 im 给的网址，后面接片段 `#miyu=<base64url(JSON)>`（片段不发给服务器、不进访问日志，票放这里比查询串安全）。JSON 是 `{"v": 1, "scheme": "light" | "dark", "colors": {...}, "ticket": "...", "lang": "zh"}`：颜色名照主题包页面那一组（下划线写法，同 WebUI 的 `design.js`），值原样（阴影是 CSS 值）。im 读完用 `history.replaceState` 去掉片段，免得票留在地址栏被复制出去。WebUI 打开前现取一张票，不缓存。
   - **命令 `/im`**：网址怎么拿到要和核心定（终端的会话建议走核心的 `command.catalog`，头不认包名）；终端照「交给系统打开」开浏览器（`xdg-open`、`open`、`start`），提示里同时写网址，SSH 进来的能复制。
5. **插件面板**：照 WebUI 的规矩开框（`package-pages.md`「框和网页之间怎么说」），桥替框做那三样事。

### 十、写法：照 Miyu 的规范、仿 Linux（2026-10-19 项目主人定）

im 照 Miyu 的写法写，不另起一套：

- **规矩**照这个仓库和核心仓库的 `AGENTS.md`：一个 `.rs` 文件不过 500 行；`cargo xtask check` 七道门禁（格式、clippy、文档、纯逻辑、行数、许可证、测试）；先有图纸（`docs/blueprint/`）和施工单（`docs/construction/`）再动手；每一步有测试，新加的测试要能在改动退回去时报红，变异照旧跑。
- **给模型看的字**一律英文、登记在 `docs/ledger.md`；**给人看的字**三种语言（中、英、日），界面上的字照 `01-接入通讯平台-界面文字.md` 和 `01-接入通讯平台-配置项.md`；代词门禁照旧（给人看的字不用「她」叫 AI）。
- **分层**：群聊内核 `miyu-chat` 是纯逻辑（不碰磁盘、网络、时钟），宿主和驱动在进程里，层与层之间只经接口（第三节的 trait、第四节的方法）。

**仿 Linux**：im 是 Miyu 这台「操作系统」里的一个子系统，照 Linux 的终端、网络子系统来搭（核心设计 18 第二节的那张表照这一份改读：「接一个新平台」从「写一个新的桥」改成「写一个新的驱动」）：

| Linux | im | 说明 |
|---|---|---|
| 一个子系统（tty、net） | 接入通讯平台 `miyu-im` | 一个包、一个进程，装了才有 |
| `postgres` 这类系统用户 | 系统账号 `im` | 场所会话归它，它的东西在自己的家目录里 |
| `systemctl start/stop/status`、`journalctl` | `miyu im start/stop/status/logs`、首页的运行日志 | 开关和看日志 |
| 设备驱动（串口、USB、网卡驱动） | 平台驱动（OneBot、Telegram……） | 把一种平台的线路协议翻译成统一的消息（第三节） |
| `file_operations`、`net_device_ops` | 驱动的 trait | 驱动实现的那一组方法，做不到的回「不支持」 |
| 网卡的 feature 位（`ethtool -k`） | 驱动的能力表 | 撤回、合并转发、贴表情……有没有，宿主照它决定工具和界面 |
| `ioctl` | 平台动作、`chat.action` | 收发之外每种平台自己的操作，原样转给驱动 |
| 驱动的 quirk 表 | 平台实现的毛病 | 照连上来的是哪个实现、哪个版本打开修正 |
| 设备节点 `/dev/tty*` | 会话（场所） | 一个群、一个私聊就是一个设备 |
| 线路规程 | 要不要开口的策略 | 主动回复判断开不开、随机进入判断的概率 |
| `/etc/default` 加 udev 规则 | 设置页的会话默认值加会话卡片 | 默认值一份，每个设备只写和默认不一样的 |
| netfilter 的链和挂钩点 | 进站链、出站链，`chat.inbound`、`chat.outbound` | 一条条按顺序过；插件挂在固定的点上 |
| 可加载的内核模块（`insmod`、`lsmod`、`modinfo`） | im 插件（`miyu-im-<名字>`） | 插件页就是 `lsmod`，详情页就是 `modinfo` |
| `/proc`、`top` | 统计页 | 计数器和用量 |
| `~/.ssh/authorized_keys` | 账号绑定 | 把平台上的身份认成本机的账号 |
| 信号 | 命令和连接状态 | `/stop` 相当于 Ctrl+C，断线相当于挂断 |

**扩展的插口**（都不用改核心，也不用改宿主）：

| 想做的事 | 插口 |
|---|---|
| 接一个新平台 | 写一个驱动（第三节）；以后也能是一个声明自己是驱动的 im 插件（第四节第 7 条） |
| 往收发里加一道 | im 插件挂 `chat.inbound`、`chat.outbound` |
| 让某种情况更容易或更不容易开口 | im 插件挂 `chat.score` |
| 往会话浮窗、首页加东西 | im 插件声明分页、首页卡片（第四节第 5 条） |
| 改新会话的默认 | 设置页的会话默认值 |
| 平台实现又出了新毛病 | 驱动的 quirk 表里加一行 |
