## 施工单 I-271：「模型」页只画供应商真有的项，「看图」改叫「多模态」

状态：做完了（2026-11-21），排进下一版，不单独发版。

### 起因

core1 自测 rc2.5 时看到 im 管理页面的两处和网页软件不一致：

1. 「模型」→「供应商」里点 Antigravity，还显示「密钥 / 粘贴密钥 / 保存 / 改用环境变量」。核心 FX-11 起 `model.list` 每家带 `needs: {key, base_url}`（`none`、`optional`、`required`）和 `package`，网页软件在主人验收第 8 条（ACC-1121-#8）已经照它只画这一家真有的项，im 这边没跟上。
2. 模型列表的能力标签还写「看图」，网页软件和核心字表（FX-9）都已经改叫「多模态」。

### 查到的

- 页面直接透传核心的 `model.list`，`needs` 已经到了页面，只是没用。
- 同一个问题还在两处：编辑表照内置驱动的样子把地址、密钥都画出来；原样点「保存」会把包给的接口连同 `package` 一起写进系统配置（`[providers.antigravity]` 下多出 `driver`、`package` 两行），盖住包的设置。网页软件验收第 8 条修的正是这个，im 照同样的办法改。
- 「看图」除了模型列表的标签，还有数据统计的用途 `stats/purpose-vision`；英文的 `field/vision-model` 还是旧说法「Vision model」。

### 改了什么

- `config.js` 加两样纯逻辑：`shows(need)`（`none` 的不画，旧核心没有 `needs` 的照旧画）、`packageValue(got, id, field)`（`config.get` 里此刻来源是 `package` 的值）。
- 供应商页：`needs.key` 是 `none` 的一家不画密钥那一块。
- 编辑表（`provider-form.js`）：`needs` 是 `none` 的地址、密钥不出那一行；包给的地址框空着、暗的占位字写包给的地址，空着存不写；包给的接口人没换的不写。新建的照旧全画。
- 添加供应商：配好了的一家不要密钥的，不出「密钥 已配置」那一行。
- 字表：`models/meta-vision`、`stats/purpose-vision` 三种语言改成「多模态」「Multimodal」「マルチモーダル」（照核心 `usage/purpose/vision` 和网页软件的 `meta_vision`）；英文 `field/vision-model` 改成「Multimodal model」（照核心 `models.vision` 的名字）。

### 怎么验

- im 没有页面脚本的测试框架，纯逻辑用一次性的 node 脚本核过：`shows` 四种取值；`packageValue` 认包给的、不认人写的；包给的接口没换、地址和密钥不画时 `providerChanges` 一项都不写，换了接口照写。
- 沙箱实测（`~/.cache/miyu-remake/needs-live`，`up.sh`；主人本机装的 rc2.5 核心，im 照这一版的页面，Antigravity 照它仓库的清单装、程序换成占位的；代理 Chromium 开 `#models`）：
  - 改后：Antigravity 下面没有密钥那一块；「编辑」只有 ID、显示名、接口三行，原样「保存」以后配置文件逐字节没变；「添加供应商」里点配好的 Antigravity 没有密钥那一行。DeepSeek（环境变量给的地址和密钥）照旧有密钥那一行，编辑表照旧画地址、接口、密钥；能看图的模型那一行写「1M 上下文 · 多模态」。
  - 对照：同一个沙箱把这几份页面换回 main 上的，Antigravity 又出现密钥那一块，编辑表多出地址、密钥两行，原样「保存」以后配置文件多了 `[providers.antigravity]` 下的 `driver`、`package` 两行。
- 门禁八项；三台 CI。
