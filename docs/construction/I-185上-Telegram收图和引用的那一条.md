## 施工单 I-185 上：Telegram 收图，引用的那一条由驱动答

状态：做完了（2026-11-10；设计 07 第 3.5 节第一版「收图给她看（静态贴纸当图）」，I-185 拆成上、下：发图、发文件、贴表情、撤回在下）。

### 为什么

- I-183 中下起，Telegram 的图、贴纸只给 AI 一个占位（`[image: 33 B]`），图本身看不到。
- 引用回复时，宿主要去取被引用的那一条，好带上它的图。Telegram 驱动答不上「取一条消息」，每次引用都记一行 `WARN picture not fetched`（11-09 真机实测看到的）。

### 怎么改

1. 收消息时，图、静态贴纸记成能照图取（`Fetch::Image`）。动的贴纸（`tgs`、`webm`）、语音、视频、文件照旧只给占位。
2. 驱动答 `Link::fetch`（`files.rs`）：
   - `getFile` 问到 `file_path`，照这个连接的代理下回来，交 base64。宿主自己的下载不走连接的代理，地址里又带着令牌，所以不交地址出去。
   - 机器人取文件最大 20 MB，问到超了的不下，下的时候读到上限就停。
3. 驱动答 `Link::message`：Telegram 不给机器人照编号取消息。收到的那一条、它引用的那一条（`reply_to_message` 带着整条）认好以后记进 `Known`（最近 4096 条，只在内存里），宿主问时照它答，没见过的答没找到。
4. 能力表多 `media`、`message`。
5. 假 Bot API 认 `getFile` 和 `GET /file/bot<令牌>/…`。Telegram 群的测试夹具（群号、Alice、叫她才回的规则、一条群消息）挪进 `support/telegram.rs`，工具的测试跟着用。

### 坑

- 旁听的那一条不取图（照宿主的规矩，冲她来的才取），引用它时才取：测试里数了下载次数。
- 实测时看到 Telegram 群的场所说明照 QQ 的模板写成了 `QQ group "…"`（`data/system/group.txt`），和这一步无关，另报。

### 验收

- 集成测试 `telegram_pictures`（真核心、本机假 Bot API）：主人引用 Alice 带图的那一条、@ 她、自己也带一张，两张都交给她看（`msg-60-1`、`msg-61-1`，引用的在前），都存成了 blob；旁听时没下，叫她时各下一次；运行日志里没有 `picture not fetched`。把图改回不取，这个测试报红。
- 单元测试：图、静态贴纸能取，动的贴纸、语音、视频、文件不取；收到的和它引用的那一条记下了，别的聊天的同一个编号对不上。
- 本机门禁、三台 CI 全绿。
