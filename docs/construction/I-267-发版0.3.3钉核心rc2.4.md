## 施工单 I-267：发版 0.3.3，钉核心 rc2.4

状态：做完了（2026-11-20），合进 main 以后打标签。

### 起因

核心 rc2.4 装到项目主人本机以后，im 0.3.2 起不来，核心日志 `extension stopped package=im reason=config_error`，主人的 QQ 机器人断了。im 的报错：

```
miyu-im: /usr/lib/miyu/resources/core/human/zh.json: unknown field `option_notices`, expected one of `name`, `description`, `options`, `option_descriptions`, `fields`, `suggestions` at line 24 column 1172
```

im 读核心资源目录里的字表（`Human::load`），用的是编进 im 的那份核心代码。0.3.2 钉的核心 `f9028fcea` 早于核心 DSR-2，那时字表的一项不认识 `option_notices`，而且拒绝不认识的字段。rc2.4 的字表带了这一格，旧的 im 就读不了。拒绝不认识的字段的是核心的 `miyu-config::words::ItemWords`，core1 在核心那边改成向前兼容；im 这边照 core1 转达的定论换钉、发 0.3.3（主人已经同意 im 跟 rc2.4 一起发，这是同一件事的补丁版）。

### 改了什么

- 核心钉 `f9028fcea` → `36bd3c4e4`（rc2.4 那一版），刷了 Cargo.lock；第三方许可证清单照新钉重写，没有变化。
- 两份清单 `version` 0.3.2 → 0.3.3，`[package]` 加 `miyu = "2026.11.0-rc.2.4"`：更旧的核心装的时候就说要更新 Miyu，不再装上了却跑不起来（I-265 时记下的待办）。
- 钉的核心在 AU-P1d 把 `Human::with_dir` 放到了 `testkit` 特性后面，im 的正式代码在用它（包文件夹的字并进核心的字）。`crates/miyu-im/Cargo.toml` 暂时给 miyu-store 打开 `testkit`：这个特性只多出这个函数和测试删临时目录的帮手，不改行为。依赖方向的测试（`crates/miyu-im-app/tests/dependencies.rs`）跟着暂时允许宿主直接依赖 miyu-store。core1 已经派人把它恢复成正式接口，下一次换钉时两处一起去掉。
- 发版说明草稿清空，开头改成「v0.3.3 以后的改动」。

### 发版

照 I-265：合进 main 以后在那个提交上打 `v0.3.3`，`release.yml` 出 6 个包；Release 填说明；下载包核对清单的版本、`miyu` 下限、程序、`site/`、`data/`；告诉 core1。
