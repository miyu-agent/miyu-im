## 施工单 I-176：im、赞助记录发 0.2.0

状态：做完了（2026-11-07；项目主人定版本号 0.2.0，core1 转达主人实测要从官方源装）。

### 为什么

官方源里 im 还是 0.1.1（11-04，be8acd2），比实时日志、网页改版、本机免密、每轮提示、看一眼条数可配这些都早。项目主人要把发版会发的东西整套装到自己电脑上实测，im 从官方源装。

### 怎么走

1. `miyu-im`、`miyu-im-sponsor` 两份清单 `version` 0.1.1 → 0.2.0。打包模板要标签 `v<版本>` 和清单的 `version` 一样，标签是 `v0.2.0`。
2. 核心照现在钉的 5ff659669（core1 11-07 定：不等核心 rc.2；换钉到最终核心留到正式发版前）。清单不写核心版本下限：rc 号照 semver 比 2026.11.0 小，会挡住主人装的演练版。
3. 发版说明草稿（`docs/next-release-note.md`）开头改成 v0.1.1 以后，删掉 v0.1.1 已经带上的三条（I-129、I-130、I-131），写明要求核心 5ff659669 以后、装的时候要批「替本机页面换登录票」。
4. 标签由项目主人在 core1、sub1 写的脚本里打（`IM_TAG`、`IM_SHA`），打了以后 Release 流水线三种系统各打两个 `.miyu`，官方源照它读。

### 验收

- 本机门禁、三台 CI 全绿。
- 标签打了以后：Release 里有六个 `.miyu`（两个包 × 三种系统），官方源里 miyu-im、miyu-im-sponsor 是 0.2.0。
