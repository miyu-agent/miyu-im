### 两页

- **清单**：

  ```toml
  [[widget]]
  id = "groups"
  place = "page"
  title = { zh = "QQ 群", en = "QQ groups", ja = "QQ グループ" }
  command = "qq-groups"

  [[widget]]
  id = "friends"
  place = "page"
  title = { zh = "QQ 私聊", en = "QQ private chats", ja = "QQ 個人チャット" }
  command = "qq-friends"
  ```

- **谁在看**：核心发 `widget.watch {widget}` 的那一块记成在看，`widget.unwatch` 的拿掉。在看的那一块，收到 `watch` 时、卡片和白名单变了以后（三个方法、`cards.save`、配置推来新的白名单）照这一刻的拼好经 `widget.set` 推一份。拼要问 NapCat 的群、好友和核心的人格（同 `cards.get`），另起任务问齐了再推。

- **「群」那一页**：
  - `sections`：「其他群」一项（编号 `other`）在最前面，然后白名单里的每个群（编号是群号，标题照群名，没有的写群号；副标题是群号）。`state`：接话的 `good`，关着的 `off`。`add`：「加一个群」，选项是她在、还没有卡的群（`群名（群号）`，100 个以内）。
  - 一项里：小标题加表单，四组：
    - 对话：接话（开关）、人格（下拉：不设、各人格）、附加提示词（多行字）。
    - 群里怎么叫她：触发词（字的列表）、插嘴（下拉：不插嘴、少、偶尔、常）、管理的人（字的列表，写 QQ 号）、看得到 QQ 号（开关）。
    - 节奏：睡觉时间（一行字，`23:00-07:00`）、限流（一行字，`3/60s`）。
    - 发出去：去句号（开关）、长文（下拉：拆成几条、转成图）、长文阈值（整数 0 到 100000）。
    - 底下按钮：删掉（「其他群」没有）。
  - 页面最后一段按钮：「私聊」（打开另一页）。
- **「私聊」那一页**：白名单成员每人一项（编号是号，标题照好友昵称，没有的写号）。两组：对话（人格、附加提示词）、发出去（去句号、长文、阈值）；按钮删掉。`add`：「加一个人」，选项是好友里还不在白名单的。最后一段按钮「群」。
- **每一格**：`value` 是卡片上写的，没写的 `null`；`default.text` 照卡片下面几层套出来的值写成「默认 · …」（同 `cards.get` 的 `defaults`），没有的「默认 · 不设」。
- **字**：给人看的写成三种语言的表，核心照每个头的语言挑；保存失败的 `message` 照桥这时的语言写（握手交来的）。

### 三个方法（`package.methods` 登记，不进 `[export]`）

- `cards.save_one {card, values}`：`card` 是 `{"kind": "other_groups" | "group" | "private", "id"?}`；`values` 只有这次改过的格，`null` 是恢复默认（删掉那一格）。照部分更新合进那一张卡，拼成规则交群聊内核读：有问题的不存，答 `{saved: false, problems: [{key, message}]}`；格的类型不对的同样一条；那张卡不在了的 `{saved: false, message}`；存好了 `{saved: true}`、当场换上、推新的内容。
- `cards.add {value}`：「群」页的 `value` 是群号（字），加一张空卡；「私聊」页的 `value` 是 `p:<号>`：经核心 `config.set {layer: "system", changes: [{key: "onebot.whitelist", value: 加上以后的, expect: {value: 现在的}}]}` 把 `qq:<号>` 加进白名单（核心 T-9 补：扩展能逐项改自己的项），再加一张空卡。答 `{id}`。已经有的照答 `{id}`；白名单改不成的（对不上、核心拒了）答 `{saved: false, message}`。
- `cards.remove {card}`：群卡删掉那一张；私聊卡删掉那一张、经 `config.set` 把那个号移出白名单；「其他群」不收。答 `{saved: true}` 或 `{saved: false, message}`。

### 施工时定的

- 群、私聊的 `add` 的值加前缀（群号原样、私聊 `p:<号>`）：一个方法分得清是哪一页来的，不用两个方法。
- 选项多过 100 个的只列前 100 个（协议上限），照群号、号排；多的在后台页的 `cards.save` 那一条路还能改。
- 改白名单带 `expect`：有人同时在别处改了白名单的不覆盖，答「白名单刚被别处改过，请再试一次」。
- 「其他群」的卡没有删掉，只有关着（接话关）。
- 人格下拉只列核心 `persona.list` 交来的（写错的不列）；卡片上写着的人格不在列表里的（删了的）照样作为一个选项放进去，免得一打开就被改掉。
- 卡片的模型这一步没有（等核心第 5 件）；改人格只对新造的场所会话生效（等核心第 6 件），这一格的 `hint` 写明。
