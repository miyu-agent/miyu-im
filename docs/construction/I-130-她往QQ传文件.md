## 施工单 I-130：她往 QQ 传文件

状态：做完了（2026-11-04；项目主人定：往群里、私聊里传文件是平台的功能，im 自己加一件工具，不设上限，`show` 不动）。

### 目的

她往 QQ 里发文件，原来只有核心的 `show` 一条路。它有两处不合用：
- `show` 是给人看的，文件超过 20 MiB 就拒；
- im 收到以后把整份读进内存、转成 `base64://` 塞进一条消息交给 NapCat，大文件吃内存。

OneBot 的 `upload_group_file`、`upload_private_file` 本来就收本机路径，NapCat 自己读、自己传。

### 怎么走

1. 驱动加 `qq_send_file {path}`（`tools/send_file.rs`），私聊、群都给，归清单的「聊天动作」。
   - 只认会话工作区（`cwd`）里的普通文件：照真实位置比，链接解开再判（core1 11-04 交代）。不认的答 `no-file`。
   - NapCat 不是从本机连进来的读不到文件，答 `not-local`。
2. 钉住（core1 11-04 审出来的）：判完到 NapCat 真去读之间有时间差。她能被人引着用 shell 把文件换成指出去的链接，NapCat 不在沙盒里、以主人的身份读，读到的就是数据根里的密钥这类。所以：
   - 判过的文件先硬链接进驱动状态目录的 `outbox/`，名字 im 起，交给 NapCat 的是这一份。
   - 链接好了再核一遍：原路径照样解在工作区里，原路径、钉住的两份和判的时候是同一个 inode。对不上的删掉、答 `no-file`。
   - 硬链接不了的（跨文件系统），和不是 Unix 的系统（核不了 inode），答 `unsendable`。不退回拷一份：拷也有同样的时间差。
   - 传完、没传成都删。每次调用顺手清掉钉住超过 `upload_seconds` 加一分钟的。
3. 认了的交给 im（`Effect::Upload`），当场答 `uploading {name, size}`，另起任务把钉住那一份的路径交给 NapCat。最多等 `upload_seconds`（新加，出厂 3600）。没传成的照 `show` 的文件记 `unshown`，QQ 收不了的就是 NapCat 回的原话。im 不设大小上限。
4. `shown.rs` 的发送任务认两种来处：blob（`show`）、本机路径（`qq_send_file`）。`show` 照旧。
5. OneBot 的连接记下对端是不是从回环地址连进来的（`Wire::from_here`、`Link::local_files`）。传文件的时限另算（`Wire::upload_wait`）。
6. 给模型看的五份：工具说明、`uploading`、`not-local`、`no-file`、`unsendable`，经 opencode Console Go 的 `deepseek-v4.1-flash` 量过，登记在 `docs/ledger.md`。工具边际 52，四句结果 15、15、16、14。
7. 工具面预算：照文件数合计 4476 字节，超了 4312。项目主人定门禁改成照模型收到的紧凑 JSON 数：文件里的换行、缩进有 210 字节，解析以后就没了。这样合计 4266，预算不动，别的说明一个字不改（`tests/budget.rs`）。
8. 给人看的：工具显示名（`data/human/*.json`）、后台页活动记录的工具名（`site/texts.js`）中英日三份。
9. 蓝图 `onebot.md` 加「传文件」一节，补文件表、调优表。
10. 新开 `docs/next-release-note.md`（下一版发版说明的草稿）：写明 Windows 上暂时不能传文件（core1 11-04），顺带补上 I-125 到 I-129 的几条。

### 验收

- 单元测试：
  - 工作区里的照相对、绝对路径都认，钉进 `outbox/`；
  - `..`、工作区外面的、目录、不在的、指出去的链接不认，去掉工作区那道检查测试变红；
  - 钉住以后原文件换成指出去的链接，钉住的那一份照旧是原来的内容，交原路径不钉测试变红；
  - 只清过了时限的；不是 Unix 的系统上不传。
- 端到端（只在 Unix 上）：真核心拉起真桥，假 NapCat 从本机连进来。她在群里调两次：
  - 工作区里的那份把钉住的路径交给 `upload_group_file`、答在传了，传完删掉；
  - 工作区外面的答不是工作区里的文件。
- 本机门禁、三台 CI 全绿。
