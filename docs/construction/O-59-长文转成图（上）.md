## 施工单 O-59（上）：长文转成图

状态：待合。O-59（下）是长文的第三种「合并转发」、命令回执太长时照同一条处理、主动发消息（`qq_send`）也照它。

### 目的

项目主人 2026-10-18 定：

1. 场所卡片多一格「长文」：拆成几条、转成图、合并转发。出厂转成图（同旧版：超过阈值的回复画成长图）。
2. 阈值每张卡能单独改，出厂 300 个字（同旧版）。
3. 转成图调渲染包（核心仓库设计 36 第八节）：`miyu-render.markdown`，一页一条图片段走出站队列；渲染包不在、画不出来的照拆段发，运行日志记一行。

### 蓝图改哪几节

- `chat.md` 第八条「对外的样子」：出站参数多两项 `outbound.long_text`（`split`、`image`，O-59 下加 `forward`）、`outbound.long_chars`（0 到上限，0 是不算长文）。
- `onebot.md`：
  - 「场所卡片」：群卡、「其他群」卡、私聊卡都多 `long_text`、`long_chars` 两格，和去句号拼进同一张 `outbound` 表。
  - 「出站队列」：多一种段「长文的一页」。
  - 「挂接点」旁边写调渲染包：没装、没开、调不通、画不出来、超时的照拆段发。
- `onebot/data/defaults.toml`：`[outbound]` 加 `long_text = "image"`、`long_chars = 300`。

### 怎么走

1. **判长文**：她的一句话过了出站链（清理、去句号、去重、引用和 @）以后，照这个场所的参数看：`long_text` 是 `image`、`long_chars` 不是 0、清理过的全文超过 `long_chars` 个字的算长文。别的照旧拆段。
2. **画**：经核心的 `package.call {"package": "miyu-render", "method": "markdown", "params": {"markdown": 全文}}`，等至多 15 秒；回来的每一页经 `blob.get`（不写 `session`：渲染包传的 blob 在管理员名下，核心补的口子里这条是正路）读成 `base64://…`。哪一步不成（没装、没开、拒了、超时、读不出）整句照拆段发，记一行 `long text not drawn why=<原因>`。
3. **入队**：一页一段，新的一种段「长文的一页」，照先后入队：
   - 第一页带全文：入队记成 `reply`（全文、线、回合，另带 `blob`），照旧算进这一回合发出去的（群里进投影、私聊进 `Spoken`），去重、补发都认它；带引用和 @（拼在图前面，同一条消息）。
   - 后面几页只有图：入队记成 `image`。
   - 群里发成了记 `venue.delivered`：第一页 `text` 是全文、`to` 是回的人，后面几页 `text` 空、`to` 空；`images` 都是那一页的 blob。
   - 没发出去的：第一页照她的话退信（`undelivered`，写全文的开头），后面几页照发图记 `unshown`。
4. **补发**（桥重启以后期限以内没入队的，`revive`）走同一条：照样判长文、画。

### 卡片

- 群卡、「其他群」卡、私聊卡都多两格，可选、没写的照下面几层：
  - `long_text`：`split | image`（O-59 下加 `forward`）。
  - `long_chars`：0 到上限的整数，0 是不算长文。
- 拼成规则时和 `strip_period` 并进同一张表：`outbound = { strip_period = …, long_text = "…", long_chars = … }`。
- `cards.get` 的默认值多这两格（出厂参数套上规则改的，来处同去句号）。

### 施工时定的

- 画的时候桥这一头等着（同发表情包读图）：长文的图要和她前后的话守先后，另起任务就会被后面的短句插队。等至多 15 秒（渲染包自己限 30 秒，平常一页零点几秒）；超了照拆段发，不卡住别的群太久。
- 判长文用清理过的全文（出站链交回来的那一份），不用拆好的几段拼回去：拼回去分不清原来的空行。
- 第一页带全文进投影和 `venue.delivered`：她的话对群里的人是「发过了」，去重、退信、补发都要认得这一句。
- 配色不在卡片里给：照渲染包自己的配置（出厂纸色）；卡片里改配色以后要的话另加一格。
- 「合并转发」这一步还不收：卡片写 `forward` 的当写错（群聊内核报 `not_an_option`），O-59 下再加，免得收了却照拆段发。

### 不做什么

- 合并转发、命令回执、主动发消息（O-59 下）。
- 后台页里改这两格（O-58 下画卡片页时一起）。

### 验收

- 门禁全过（格式、clippy、文档、登记簿、纯逻辑、行数、许可证、整套测试、测试登记）。
- `tests/long_text.rs` 五条（真核心拉起真桥、假 NapCat，测试包扮渲染包）：超过阈值的回话发成两条图片段、内容是那张图，她 `mention` 的 @ 只在第一页；入队 `reply`、`image`；`venue.delivered` 第一页带全文和回的人、第二页都是空的；渲染包收到的、记下的都是过了出站链的全文（去了末尾的「。」）、`from` 是 `onebot`。不长的照发字、不调渲染包；渲染包没装的、交回零页的、群写了 `long_text = "split"` 的照发字。

  - 第一轮漏了五个（交回零页的吞掉回话、第二页带 @、第二页记回的人、判长文用原话不用清理过的、阈值的来处照错格），补了测试；两个锚点被格式化改过，改了重跑。
