## 施工单 I-91：QQ 工具拆成三个功能

状态：做完了（2026-10-30；项目主人 10-30 定预设功能分组，核心 FG-1 照它在预设页分组）。

### 目的

im 的十九件工具在预设里只是一个开关「QQ 工具」：终端里只想让她查记录，也得把禁言、踢人一起开。项目主人定照后果分成三个功能：聊天动作（别人看得见）、查询信息（只读）、群管理（管人）。按群开关的插件也跟着改：原来的「群聊记录」「群资料」并成「查询信息」，免得预设里一个叫法、插件页里另一个叫法。

### 图纸改哪几节

- 蓝图 `onebot.md`：软件包清单（三个功能）、能力那一段、平台工具几处「预设关了…的会话没有」、「查询信息」那一段（原「群聊记录、群资料」）。

### 怎么走

1. 清单：`[features.qq]` 换成 `im-chat`、`im-lookup`、`im-admin` 三个，各列自己的工具（核心 T-2：写了几个功能的，哪个都没列的工具整批不收）。编号带 `im-`：功能编号跨包撞了整个包不收。
2. 插件：`crate::lookups` 的 `Records`、`Info` 并成 `Lookup`（`miyu-im-qq-lookup`，总开关 `lookup_on`）；工具套照 `LOOKUPS` 认这八件归它。清单的两个开关 `records_on`、`info_on` 换成 `lookup_on`。
3. 显示名（项目主人定）：不说话 → 不回复，@ 群成员 → 艾特，查聊天记录 → 查询聊天记录，取图和文件 → 获取图片和文件，取头像 → 获取头像；查询类统一「查看…」（群成员、群公告、群文件、通讯录、发言排行、管理记录）。英文、日文跟着改对应的几件。
4. 搬家脚本（仓库外，`~/.cache/miyu-remake/im-migrate`）：卡片上两个旧插件的开关合成一个，两个都开着才开、有一个关的就关。

### 不做什么

- 线上的配置里没写过 `im.qq.records_on`、`info_on`（10-30 只读查过），配置不搬。
- 预设里没写过旧功能 `qq`（同上），预设不搬：新的三个功能照每个预设的 `unlisted`。

### 验收

- `every_tool_belongs_to_exactly_one_feature`（驱动交的每件恰好归一个功能，清单不多列；变异：清单删掉 `qq_kick`，报「qq_kick 归 []」）、`the_lookup_feature_is_the_lookup_plugin`。
- `the_lookup_plugin_switches_its_tools`（真核心）：出厂八件都在；卡片上关了八件都没有；卡片恢复、总开关关了也都没有。
- 显示名、登记的 `plugin`、驱动配置项、插件名单的测试照新名字改了。
- 本机门禁、三台 CI 全绿。
