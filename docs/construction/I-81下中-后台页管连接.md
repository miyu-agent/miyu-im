## 施工单 I-81 下中：后台页管连接

状态：做完了（2026-10-30；设计 07 第 7.7 节，项目主人 10-30 定连接只在 im 后台页改、Token 每个连接一个）。

### 目的

I-81 下上让驱动照连接表开端口，这一步让人在后台页加、改、删连接：新建连接多填一个端口，存成表里新的一个；连接卡的齿轮改它那个端口的一项；配好了还没连上的连接也有一张卡。

### 图纸改哪几节

- 设计 07 第 7.7 节（已写，这一步照它做）。

### 怎么走

1. 宿主记下号从哪个端口进来：连接接口多 `listen`（默认空），OneBot 的连接记下端口；断开了的号也记着原来的端口。页面的 `connections` 每个号带 `listen`。
2. 三个方法（`site/connections.rs`，人的连接上替人读写）：
   - `connection.add {port, token, host?}`：端口 1024 到 65535、不和表里的重，Token 必写。
   - `connection.edit {port, values: {host?, listen?, token?}}`：改那个端口的一项；`token` 空的不改。
   - `connection.remove {port}`：表里只剩它的不删（`last_connection`）。
   - 读：`config.get` 三个列表；表没写过的，原来设了 Token 的三项当头一个连接，没设的不算（新装的头一回新建就是头一个）。写：Token 先 `secret.set` 存成 `im-qq-token-<端口>-<时刻>`，三个列表一次 `config.set` 写，原来的三项一起去掉。
3. 页面：
   - 首页读 `status` 的 `connections`：设了 Token、还没有号从它的端口进来过的，排在机器人的卡后面一张「等 NapCat 连上」，写端口；连接那一栏的数照旧只数机器人。
   - 齿轮：机器人照它进来的端口找表里那一项，「等 NapCat 连上」的就是它那一项；格里照它填，保存经 `connection.edit`；表里不止一个的多「删除这个连接」，点一次换「再点一次删除」，再点才删。找不到那一项的（表没写过）照旧经 `connection.save` 改原来的三项。
   - 新建连接：填地址那一步多一格端口，先填表里设了 Token 的端口最大的加一（表里还没有的照 `status` 的端口），和表里的重了说「这个端口已经有连接了」、不让往下走；粘贴 Token 那一步经 `connection.add` 存；等连上照这个端口认号。

### 不做什么

- 终端里主动发消息选号：I-81 下下。
- 删了的连接的密钥不删（人的密钥库里多一条没人用的，`secret.list` 看得到「没人用」）。

### 验收

- `site::connections` 的三条单元测试（照端口那一列读、没写表时设了 Token 的原来三项是头一个、写回三列加去掉原来三项）。
- `the_page_adds_edits_and_removes_connections`（真核心）：原来那一个设了 Token，加一个以后表里两个、原来的三项去掉、新 Token 存成密钥；改端口、地址，Token 空的不改；端口重了、Token 没写、找不到、端口超出范围都是 `bad_params`；删一个，剩一个以后 `last_connection`。
- 截图自测（临时夹具，不提交）：一个号连着、表里另有一个没连上的端口：首页两张卡（机器人、「等 NapCat 连上 · 端口 …」）、数字写「1 个机器人」；「等 NapCat 连上」的齿轮里格照那一项填、有「删除这个连接」；新建连接第一步端口先填好、地址跟着端口变。
