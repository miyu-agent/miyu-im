## 施工单 I-249：插件页列关着的插件

状态：做完了（2026-11-18），等项目主人验收。钉核心 main `80d8672d1`（UX-1修）。

### 起因

核心 UX-1、UX-1补（项目主人 11-17 定「关了就全没」）以后，关着的包带给 im 的目录不进 `content.list`，im 读不到它的 `plugin.toml`。im 的插件页原来只列 im 读到的插件，关着的就从页面上消失了，也没法在页面上把它打开。换钉到 UX-1 以后的核心，`plugins::a_plugin_installed_while_running…`、`site_plugins::the_plugin_page_lists…` 两条测试红（它们期望关着的、装了还没开过的插件读得到）；第三条 `hooks::…` 是核心 UX-1 的回归，core1 修了（`80d8672d1`）。core1 定：核心照旧不交关着的包的内容，im 的插件页改从 `package.list` 取关着的插件。

### 改了什么

1. `site/plugins.rs`：`plugins.list` 在 im 读到的插件以外，加上 `package.list` 里 `enabled` 为假、`provides` 的 `content` 有 im 的包（[`off`]），只有包名、核心照连接的语言挑好的 `name`，并上核心说的版本、开关这些；`plugins.enable` 认关着的插件，开得了；`plugins.readme` 碰到关着的回 `not_found`。
2. 页面 `named()` 收一个字符串（关着的插件只有核心挑好的名字）。
3. 两条测试照新规矩改期望：`manual` 的包装上以后打开才读到；插件页一开始只读到开着的，关着的照 `package.list` 列，开关以后等 im 重读。
4. 蓝图 `extending.md`「关着的插件」。

- 退回（不列关着的）插件页那条红；门禁七项全过。
