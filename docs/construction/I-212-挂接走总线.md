## 施工单 I-212：总线第二步——插件挂接接进 `chat.hook`

状态：做完了（2026-11-11）。换钉核心 095732ba9（`bus.list` 的行里带 `methods`）。核心设计 `67-总线.md` 的 BUS-4 里归 im 的三步之一（I-211、I-213）。

### 为什么

im 原来自己搭了半个总线：订阅软件包列表，找 `export.methods` 里有 `chat.event` 这类名字、`status` 是 `running` 的包，经 `package.call` 调。核心有了总线以后这件事归它：插件声明接进哪个名字，im 照名字找。BUS-5 要收掉扩展经 `package.call` 调别的包这条路。

### 改了什么

1. **名字**：im 的插件在清单 `[export]` 里声明 `plugs = ["chat.hook"]`，四处的方法是 `chat.hook.event`、`chat.hook.inbound`、`chat.hook.outbound`、`chat.hook.score`（原来 `chat.event` 等）。老名字不再认，不留两条路（核心设计 67 B6：同一个名字只能是一种，im 自己 `provides` 了 `chat`，挂接只能另起名字）。
2. **找谁**（`core/hooks.rs`、`core/hooks/follow.rs`、`core/route/packages.rs`）：订阅 `bus` 流（原来 `packages`）。`name` 是 `chat.hook`、`kind` 是 `plugs` 的每一行，照行里的 `methods`（那个包已经登记上的方法的短名）认它挂在哪几处；没登记的不算，不再看 `status`、`export.methods`。推来的 `bus.changed` 是整份，照换。行为上的一处变化：光在清单里写了挂接、程序没登记那个方法的包，原来算挂上（调它时才失败、记一行 `hook failed`），现在不算。
3. **先后**：回应和推送仍走两条路。回应晚到、这次订阅以后推来过的，照推来的那一份（推的是整份，只留最后一份，比原来一项一项补简单）。
4. **怎么调**：`bus.call {"name": "chat.hook", "package": <哪一家>, "method": <短名>, "params"}`，参数、回应、等多久、出错怎么记都没变。运行日志里的 `point=` 写全名。
5. 插件页显示「挂在哪几处」仍照软件包列表里清单导出的名字读（没在跑的插件也要显示），认新名字；界面上的字的键跟着改名。
6. 测试用的插件清单：导出了 `chat.hook.` 开头的就声明 `plugs`。
7. 蓝图 `extending.md` 第二条、`onebot.md`「挂接点」、作者说明（中英）照改。
