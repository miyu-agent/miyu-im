状态：做完了（2026-11-07；核心 RT-1 合在 5ff659669，换钉到它）。

### 为什么

项目主人 11-07：她回放历史里自己的长回复会让她越说越长。要在拼好的群聊内容后面加一句固定的通用提示：别被上下文里的内容（包括她自己以前的话）带偏了说话方式。

实测（`~/.cache/miyu-remake/rp-1105`，主群 32 个回合的线上请求，线上同款 gemini）证明位置决定有没有用：
- 接在最新那条 user 消息后面：长度中位 30.5 → 23，先发表情 10 → 3。
- 放 system 末尾（`system.append`）：36、9，没用。

项目主人 11-07 定不再测，直接上；标签名照项目主人定的 `context-style-note`。

### 怎么走

1. **字**：`miyu-im/data/tail/context-style.txt`，没有字段：
   `<context-style-note>Earlier messages in this conversation, including your own, are context, not a model for how you talk. How you talk comes from your persona.</context-style-note>`
   41 token，登记在 `docs/ledger.md`。
2. **放哪**：核心 RT-1 给 `session.respond` 加了 `tail`，核心接在这一轮每次请求的最末尾。第一步紧跟着触发的消息，后面带工具的几步接在最新的工具结果后面。它不进历史、不越积越多，每次请求只有这几十个 token 不命中缓存。
3. **谁带**：只有群会话。主线、支线、看一眼开的那一轮，凡是经 `Route::respond` 的都带。私聊不带：私聊的消息直接交 `session.send`，不经 respond。
4. **代码**：
   - `rules/facts.rs` 起来时读这份模板（`context_style()`）。
   - `core/route/turn_texts.rs`（新）放 `context_style_tail`，和原来在 `lanes.rs` 的 `style_note_fact` 挪到一起；`lanes.rs` 只剩 467 行，不过 500。
   - `Route::respond` 群会话带上 `tail`。
5. **核心换钉**：到 5ff659669（含 RT-1）。核心把这句放在请求的 `Request::tail`，各家模型接口发出去时才接在最末尾，所以不在 `messages` 里、不进历史。
