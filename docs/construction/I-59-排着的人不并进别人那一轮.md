## 施工单 I-59：排着的人出队时不并进别人那一轮

状态：做完了。

### 目的

项目主人 10-27：部署到群里的 Miyu 回复对象错乱。

21:09:36 她回「看方向了，通常一门…像 Python…」，答的是紫藤沙喵 21:09:17 问的「程序员要掌握什么语言」，却同时 @ 了 yueyinqiu，他马上回「@Miyu 错乱了吧」。会话日志里事情是这样发生的：

1. yueyinqiu 21:07:52 叫她：主线在回紫藤沙喵（gentoo 的图），支线也满了，在桥里排着（I-16）。
2. 21:09:17 紫藤沙喵追问：同一个人，`JoinMain` 交给核心。那一轮快结束了，没再请求，核心照它排着的开了下一轮（turn 5617）。
3. 桥收到上一轮 `turn.ended` 就让 yueyinqiu 出队，这时 5617 的 `turn.started` 还在推送里没收。桥当主线空着交上去，核心把他并进了 5617（`turn.joined`）。
4. 这一轮的触发里有两个人，回的人取并集，第一句就 @ 了两个人。开轮带的「你只回 msg=A」和并进来的「你只回 msg=B」也互相打架。

今晚 211 句里只有这一次 @ 了两个人。

### 改了什么

- `waiting.rs` 的 `next_waiting`：出队以前先把这个群留着没办的推送收进投影（`catch_up`），再照分派办。
  - 又是 `Queue` 的（主线又在回别人、支线满了）放回队头（`push_front`），记 `INFO queued reply still waiting`，等下一轮结束。
- `lanes.rs`：分派的判断抽成 `line_for`，分派和出队共用（`should_wait`）。
- 蓝图 `onebot.md` 分派那一段加一款。
- 顺带：设计 07 两处 LG-1 改成 LT-1（核心更正的编号，miyu-agent-f4 交来的补丁）。

### 测试

- 新加 `tests/lanes_waiting.rs`（真核心）：主线回 A、支线回 B、C 排着，A 追问，A 那一轮完了：
  - C 不和 A 在同一轮；
  - C 单开一轮。
- 变异（不收推送、不放回队头）：这条没抓到。测具里压着的请求（Lines）期间来的追问，总被核心在下一步的边界并进 A 那一轮，核心不会另开一轮，压不出现场那个「这一轮没再请求就结束、核心接着开下一轮」的时序。修法照现场日志定。这条测试只守「排着的人单开一轮」。

### 验收

本机门禁 `cargo xtask check` 全过，CI 三台全绿。部署后看群里，同时叫她的人多的时候，她一句话不再 @ 两个不相干的人。日志里出现 `queued reply still waiting` 说明这条路走到了。
