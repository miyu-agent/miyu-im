## 施工单 I-85 下：统计并进首页

状态：做完了（2026-10-30；设计 07 第二节第 3 条）。

### 目的

设计 07 第二节第 3 条：侧栏去掉「统计」，首页的「统计」一栏有今天、7 天、30 天，收到、回复、只记录、没发出去，模型请求、token、缓存命中率、回复率，每天的消息，最热闹的会话，运行日志，都跟着选中的连接；「全部」时每条标上是哪个连接。I-85 中做了选中的连接，统计页还是单独一页、照第一个驱动的平台算，首页的「今天」四个数和日志不分连接。

### 图纸改哪几节

- 设计 07 第 7.5 节：原来的 I-85 下拆成下（统计并进首页）、补（卡片开关照能力藏、「本人的平台 ID」选平台）。
- 方法的写法在 `crates/miyu-im/src/site/methods.rs`、`site/stats.rs`、`site/logs.rs` 的模块说明里。

### 怎么走

1. 选中的连接（`site/scope.rs`）：参数 `connection` 写 `<平台>:<号>`，没写的是全部，写错的拒 `bad_params`。I-81 以前的场所编号不带机器人号，同一个平台的几个连接分不开，照平台算；带号的认号。
2. 计数（`counters.rs`）：收到的按小时多记一份按连接分的（`connection_hours`，键是场所编号去掉种类、号的那一段，`connection_of`）。以前写的那几天没有这一格，选了连接时按小时是零。
3. `stats {period, connection?}`：
   - token 只算选中连接的场所会话，没写的是全部场所会话（原来没写的照第一个驱动的平台）。
   - 消息：选了连接的收到、回复、只记录、没发出去、每天的照场所加起来，最热闹的会话只列它的，按小时照按连接记的；判断的原因不分场所，选了连接的不给（页面也没画它）。
4. `logs {level?, limit?, connection?}`：带场所（`venue=`）的行只要选中连接的，不带场所的（起来、出错这些）照旧都要。
5. 页面：
   - 统计页挪成首页的一栏（`pages/home/stats.js`、`stats.css`），三段照旧（token、消息、运行），消息那段多一格「只记录」；侧栏去掉「统计」，旧的 `#stats` 落到首页。原来首页的「今天」四个数去掉（并进消息那段）。
   - 跟着首页选中的连接问；宿主一推首页就再问一遍，统计（要问核心的用量账本）同一个连接 30 秒以内不再问。
   - 看「全部」、连接不止一个时：会话前面画平台标志，活动日志的场所前面写平台。
   - 统计里的会话链接带上它的连接（`#venues/group/777?c=qq:10001`）；网址里的连接变了（点了这种链接、前进后退）页面照网址的选。
   - 活动日志拆场所编号改成从右边拆（带机器人号的也认得）。

### 不做什么
