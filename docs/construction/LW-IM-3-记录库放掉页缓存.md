## 施工单 LW-IM-3：聊天记录库、用量账本安静下来放掉页缓存，自带的 SQLite 不留小块内存池

状态：做完了（2026-11-23）。

### 为什么

聊天记录库的写的线程（`im-records`）和用量账本各开着一个 SQLite 连接，一直不关。写过一阵以后连接的页缓存涨到 SQLite 的上限（默认约 2 MB）一直占着：2026-11-23 用 heaptrack 量过，5 个群灌 5000 条以后，活着的堆里 SQLite 占 2.31 MB，几乎都是记录库写全文索引时读进来的页。另外每个连接开库时先分配一块小块内存池（lookaside），空闲时一格都不用。核心 LW-15、LW-23 做过同样的两件。

### 怎么改

1. 安静下来（LW-IM-1 的同一个触发）先放页缓存、再还堆：
   - 记录库：交给写的线程一件「放掉」（`PRAGMA shrink_memory`），等它放完，最多等 1 秒；它正排着等库锁的那一次不等，下一回安静下来再放。写的线程收的东西从 `Write` 换成 `Job`（写一件，或者放掉），排在前面的照样先写。
   - 用量账本：锁上连接、同样放掉。
   - 放掉以后下一次写照常从库里读要的页，行为不变。
2. 仓库的 `.cargo/config.toml` 加 `[env]` 的 `LIBSQLITE3_FLAGS = "-DSQLITE_DEFAULT_LOOKASIDE=0,0"`（同核心 LW-23）：libsqlite3-sys 编自带的 SQLite 时照它多一个 `-D`。外面已经设了的照外面的。

### 测试

- `records/tests.rs`：
  - `shrinking_the_cache_keeps_every_write`：交 300 条再放、放完再交一条，库里一条不少。
  - `the_bundled_sqlite_keeps_no_lookaside_pool`：`PRAGMA compile_options` 里有 `DEFAULT_LOOKASIDE=0,0`（MSVC 上末尾多一个逗号，只认开头）。
- 门禁全过，原有的测试一条没改。

### 量（沙箱，5 个群各 1000 条，安静 30 秒；改前改后各三遍交替着量，PSS，kB）

| | 改前 | 改后 |
|---|---|---|
| PSS | 33333 / 33245 / 33118 | 31424 / 31031 / 31092 |
| 线程分配区 | 17516 / 17552 / 17596 | 15680 / 15432 / 15564 |

heaptrack（各一遍，同样灌完、安静 30 秒时活着的堆）：SQLite 分配的 2.31 MB → 72 KB，活着的堆合计 7.46 → 5.24 MB。

### 不做的

- 页面上读、AI 查聊天记录时另开的连接：用完就关，不常驻。
- 把页缓存的上限调小：放掉以后已经不常驻，调小只会让一阵写的时候多读盘。
