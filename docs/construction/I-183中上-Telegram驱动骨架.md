## 施工单 I-183 中上：Telegram 驱动的骨架

状态：做完了（2026-11-09；设计 07 第 3.5、4.5 节、第八节 8.3；项目主人 11-09 定做成 im 内置的驱动）。

### 为什么

接 Telegram 的第一块：连得上、知道连着谁、出了毛病报得出来。收发消息、工具、页面在后面几步。

### 怎么改

1. 新 crate `miyu-im-telegram`（只依赖宿主和门面）：
   - `api.rs`：Bot API 的一次调用（`POST <地址>/bot<令牌>/<方法>`）。HTTP 客户端用核心同一版 reqwest、共用核心的 TLS 配置，多开 `socks`（这一版用 hyper-util 自带的，不多带包）；代理一个连接一份：跟随联网设置（环境变量，同核心）、直连、照写的地址。401、409、429（照 `retry_after`）、网络出错分开交；出错一律先去掉网址（带着令牌）再记。
   - `settings.rs`：配置 `im.tg.tokens`（一列密钥）、`im.tg.proxies`（一列字）、`im.tg.api`（Bot API 地址，出厂官方的，测试指假服务器）。同一个令牌写两次只认第一个。
   - `bot.rs`：一个连接跑起来：`getMe` 认号（照回的 `id`）、名字（名加姓）、用户名、隐私模式；登记进宿主的 `Bots`、告诉宿主连上了；长轮询 `getUpdates`（挂 50 秒，只要 `message`），收到第几条写进状态目录 `<号>.offset`（先写临时文件再改名），重启接着收；409 报 `elsewhere`、拿掉登记、隔 30 秒再试；401 报 `token`、不再试；连不上、挂超时报 `network`、退避重连。这一步收到的消息先不交宿主（I-183 中下）。
   - `running.rs`：照连接表每个连接一个任务；配置变了，令牌、代理、地址都没变的照旧跑，别的放下、起新的；各连接的状态合成 `connections` 报给宿主（页面的 `status {platform: "tg"}`）。一个连接都没有照样起来，不联网。
   - 能力表先是空的，随后面几步加。
2. 程序挂两个驱动（OneBot、Telegram），清单 `[connection] platform = ["qq", "tg"]`、多三项藏起来的 `settings.tg.*`。
3. 宿主：给别的包调的方法、工具没写 `platform` 的，原来照「挂了几个驱动」判，程序编进 Telegram 以后只用 QQ 的人没写平台的老插件全被拒（老测试 25 个红）。改成照「用着」的平台判：这一回起来以后连上过号的（连着的、断开在重连的）；一个都没连上过的照第一个驱动（`Platforms::used`、`ours`）。只挂一个驱动时和原来一字不差。`extending.md` 照改。
4. 程序 `status` 的 `platforms` 现在是 `["qq", "tg"]`，三个测试跟着改。

release 编、真核心拉起程序、只配 QQ，起来后静 20 秒读 `VmRSS`，改前（df5d3cb）改后交替各三次（量尺留成 `footprint` 测试，标 `ignore`）：

### 坑

- 核心交一列密钥时原来交的是引用本身（`{"secret": …}`），驱动读不到令牌，这一步的测试过不了，查下去才发现后台页存过连接表的 QQ 连接同样拿不到 Token：核心 SL-1 修，im 换钉单独一步（I-184）。im 的测试一直用假核心直接交字，真核心的路没人走过。
- 程序编进第二个驱动以后，「挂着几个平台」和「用着几个平台」不是一回事（第 3 条）。以后再编进别的平台照此。

### 验收

- 集成测试 `telegram`（真核心、真程序、假 Bot API）：连上报号、名字、用户名、隐私模式；收到第 41 条以后照 42 收，重启以后接着照 42 收；409 报 `elsewhere`、不连着、1 秒里只试一次；401 报 `token`、只调一次、运行日志里没有令牌。改坏两处验过：不记 offset 时重启那条红，409 以后不等时「不抢」那条红。
- 宿主单元测试：只用 QQ 的、只用 Telegram 的、都没连上过的、断开在重连的，没写平台各算哪个。
- 驱动单元测试 12 个（回应怎么读、代理写法、连接表、名字、状态、offset 落盘）。
- 本机门禁、三台 CI 全绿。
