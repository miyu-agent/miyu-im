状态：做完了（2026-11-19），等项目主人验收。钉核心 main `f9028fcea`（含 O-34 补 `bcda0c875`）。

### 起因

I-253 去掉 im 自己的转发限额以后，还剩核心那道整条上限：一条场所消息所有转发合起来 100 条、名字和正文 16 KiB、一条正文 4096 字节，超了核心整条拒收。主人本机 11-17 那条 99 条的转发照样看不全。项目主人 11-19 定「这不是需要熔断保护的地方」，core1 派核心 O-34 补去掉，套几层抬到 8 层只为防栈，剩下的天花板是连接上一行 1 MiB。

### 改了什么

1. 钉核心 `f9028fcea`。
2. `route/forwards.rs`：
   - 去掉照核心旧上限写死的 `ALL_NODES` 100、`ALL_BYTES` 16 KiB、`TEXT_BYTES` 4096 和截正文的 `clip`。
   - 改成照写进 JSON 以后的字节数（名字、正文、带的东西的记号，加上键和引号的余量）一条条放，合起来到 `LINE_BUDGET` 960 KiB 为止，留 64 KiB 给这条消息别的格。
   - 放不下的算进 `more`，消息照记，不被核心整条拒收。引用的那一条走同一份预算。
3. `bridge.json` 的 `forward_depth` 3 → 8，同核心。
4. 蓝图 `onebot.md` 出厂数表、「群消息」那条、测试说明照新的写。
