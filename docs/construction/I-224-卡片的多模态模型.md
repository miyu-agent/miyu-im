## 施工单 I-224：卡片的多模态模型

状态：做完了（2026-11-11）。

### 为什么

todolist 第 34 条：会话卡片的模型设置加一项「多模态模型」，放在「上下文窗口」下面；「主动回复判断模型」加一段说明。原来看图的模型只有系统一层（`models.vision`），核心 VM-1（3e1bea773）让会话能钉自己的（`session.configure` 的 `vision`）。

### 改了什么

1. 场所规则多一项 `vision`（群聊内核 `rules/attrs.rs`，写法同 `model`：`<供应商>/<模型>` 或 `@<池>`），卡片的 `rules.vision` 写进规则（`rules/cards/lines.rs` 的 `TOP`）。
2. 钉到会话上（`core/route/policy.rs`）：同对话模型，第一次找到会话时设了的发，卡片换了的发，清掉的交 `vision: null` 回到跟着 `models.vision`。
3. 卡片模型那一组「上下文窗口」下面一格「多模态模型」（模型选择框，空着显示设置里的多模态模型）；「主动回复判断模型」下面一行说明。说明照程序实际的写：项目主人原话是「未设置模型则使用对话模型」，实际先用轻量池，问过主人确认（11-11）：「用于回复判断的模型，仅开启回复判断时有意义。未设置时使用轻量池的模型，轻量池为空时使用对话模型。」中英日三份。
4. 换钉核心 3e1bea773（VM-1，含 PS-2：预设菜单只列带 `local` 的）。

### 怎么验

- 单元测试 `the_vision_model_goes_like_the_model_and_a_cleared_one_is_null`。
- 集成测试 `card_vision`：卡片设了的群，交第一条消息以前钉上（核心记 `session.policy_changed` 的 `vision`），换了跟着换，清掉的记空的。第一遍红：`vision` 没进卡片写规则的那张表，规则里没有，加上就过；把第一次发的那一格去掉也红。
- 本机门禁七项。
- 主人实测：卡片模型那一组看「多模态模型」在「上下文窗口」下面，「主动回复判断模型」下面那一行说明。
