## 施工单 O-43 上：挂接点（上）：找到挂了的包、QQ 事件

状态：施工中。2026-10-17 项目主人定：别的包能插进接入QQ 里面，先开四处：进站（判断回不回之前）、出站（她的话发出去之前）、QQ 事件通知、判断打分。核心 F-11（3e0f621e）给了 `[depends] packages` 和 `package.list` 的 `export`。四处拆三步：上（这一步）找到挂了的包、QQ 事件；中，进站；下，出站、判断打分。

### 目的

接入QQ 的新功能做成单独的包，不改接入QQ 自己的代码：别的包导出约定名字的方法，接入QQ 在那一处调它。这一步搭起「找到谁挂在哪」，接上最简单的一处：QQ 事件。

### 蓝图改哪几节

- `extending.md` 第二条「插进接入QQ 里面」：清单怎么写（`[depends] packages = ["onebot"]`、`[export] methods = ["qq.event"]`）、`qq.event` 的参数，进站、出站、打分随后面两步写。
- `onebot.md` 第一条加「挂接点」：
  1. **找谁**：握手以后订阅核心的 `packages`（回应同 `package.list`，之后推 `package.changed`），照每一项的 `export.methods` 记下谁导出了桥认的名字，`status` 是 `running` 的才算；照包的编号排先后；掉了队（`resync`）重新订阅；核心拒了订阅的记一行 `WARN packages not followed`，照没有挂接点跑。
  2. **怎么调**：经核心的 `package.call`；桥的清单加能力 `packages.call`（出厂的包算批过的）。
  3. **`qq.event`**：NapCat 推来的 `notice`、`request`（带得出 `self_id` 的）原样交 `{"bot", "event"}`，在桥认它以前、不管桥认不认；各起一个小任务发、不等回应；核心拒了、别的包答错的记一行 `WARN hook failed package=… point=qq.event why=…`。
- 核心钉到 3e0f621e（F-11）；回放测具的 rev 一起换。
- 测试用的别的包的程序 `miyu-onebot-test-hook`（`src/bin/`）：只用已有的依赖，发版不带。
