## 施工方案

接入QQ 的施工从 O-40 起写在这个仓库里（2026-10-16 拆仓，核心仓库设计 `32-仓库拆分.md` 第九节）；O-1 到 O-39 的施工单、施工图上的 O 线芯片是历史，留在核心仓库的 `docs/construction/`。

### 一、怎么施工

1. 一步一张施工单，写在这个目录里，文件名 `O-<编号>-<名字>.md`。只写目的、图纸改哪几节（改前、改后）、要拍板的、不做什么、验收、风险。先商量、拍板，再动手。
2. 一步一个工作树：从 main 开分支 `step/O-<编号>-<名字>`，检出到 `.worktrees/O-<编号>-<名字>/`。先写证明它对的测试，修 bug 先写能复现它的、修之前是红的。
3. 写完手写 15 个左右的变异（把关键的一行改坏，对应的测试要红），机械的步子少一些。
4. 本机 `cargo xtask check` 全过；推 `step/` 分支跑三平台 CI，全绿算验收的一部分。
5. 验收通过才整理：这一步的改动合成一个提交，顺手做的无关改动单独成提交，每个提交都能编译、门禁全过；rebase 到最新的 main，快进合进 main、推送。
6. 合完在下面第二节记一行，删工作树、本地和 GitHub 上的分支、编译产物；改到协议、核心接口的，告诉核心的主会话。
